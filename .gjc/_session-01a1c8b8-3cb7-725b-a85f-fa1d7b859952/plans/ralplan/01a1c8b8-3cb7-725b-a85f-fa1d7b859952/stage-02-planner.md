# R2 계획 — goal-2 / goal-3 (정정 완전본)

## Summary
계획 전용. 제품·기획서·테스트를 수정하지 않고 모든 테스트·게이트·포매터·브라우저 실행을 생략했다. stage-01-planner.md의 AC-6 원문 전사 오류를 바로잡은 완전본이다. 이전 stage1의 해당 오류를 채택하지 않는다. 이 계획 저장은 구현 승인이나 사람 검토 완료가 아니다.

읽은 근거: AGENTS.md, GAME_DESIGN.md v1, src/logic.js, src/main.js, test/logic.test.js, 원 인터뷰 .gjc/_session-01a1c851-6892-733d-9f93-49c114e9c76e/specs/deep-interview-lighthouse-r0.md, 추가로 src/levels.js·src/sprites.js·index.html·test/index.js.

현재 logic은 입력 순간 논리 이동·120ms 표시 보간·방향키 눌림 관리만 제공한다. isPassable은 .과 P만 허용한다. main은 방향키만 전달하며 RAF는 그리기만 한다. 테스트는 #.P whitelist와 Enter 무시를 명시한다. 타이머·등불·유령·점수·화면 상태·strings.js는 없다. 팔레트 8색과 240×192 논리/720×576 표시 크기는 보존한다.

## Intent Diff
- goal-2: 승인된 레벨 1의 등불 5개·유령 1마리·60초·점수·HUD 및 승패 순수 판정.
- goal-3: 타이틀·플레이·클리어·실패의 실제 표시와 승인된 Enter 전환. 실패 Enter는 타이틀 복귀 및 점수 0.
- 먼저 별도 승인된 실행 단계에서 GAME_DESIGN 2/3/4/5/9장을 갱신하고 사람에게 보여 준다. 현재는 변경하지 않는다.
- 기존 AC-1~7 원문·번호·R1 확인 이력을 보존하고 AC-8~30을 제안한다. R1 한정 부재 조건은 R2 부재 조건으로 확대 해석하지 않는다.
- 7장 정확 문구·사운드는 R3 보류. 레벨 2/3 데이터·저장·최종 화면을 당겨오지 않는다.

## Decision Drivers
1. 문서 우선·사람 승인: 원 인터뷰는 후속 문서화 근거이며 제품의 유일한 구현 기준은 검토된 GAME_DESIGN이다.
2. 즉시 논리 이동·400ms·실패 우선·점수 공식의 재현성: 화면 보간이나 프레임 수가 판정 기준이 아니다.
3. R2/R3 경계의 정직성: 없는 다음 레벨을 가짜로 구현하거나 Enter 무시를 임시 기능으로 넣고 완료라고 하지 않는다.

### Principles
- 확정 수치는 유지하고 미정은 제안/승인 대상으로 표시한다.
- 판정은 canvas 없는 순수 함수, 시간은 호출자가 주입한다.
- 문자 격자가 배치의 유일한 원천이며 별도 좌표 목록을 만들지 않는다.
- terminal은 한 번 확정하고 이후 점수·시간·유령을 동결한다.
- 테스트는 증거 일부이며 완료는 실제 브라우저 사람 확인이다.

## Options
### 갱신 비교
A(권고 제안): 기존 즉시 입력 전이를 확장하여 입력 또는 시간 전이 호출 1회를 같은 갱신으로 정의한다. 그 호출에 포함된 미처리 유령 기한과 현재 입력의 이전/이후 논리 위치로 같은 칸 및 맞교환을 판정한다. 기존 입력 즉시성에 맞지만 호출 순서와 시간 동률의 포함 범위를 명확히 승인받아야 한다.
B: 프레임별 입력 묶음. 같은 프레임 충돌을 설명하기 쉽지만 논리 이동을 다음 RAF까지 늦추면 원 규칙 위반이다. 입력 즉시성을 입증하는 설계 없이는 채택하지 않는다.

### 클리어 Enter 경계 비교
A(권고): R2 레벨 1 클리어까지의 단계 확인과 R3 데이터 이후 다음 레벨 진입 확인을 분리한다. 이 단계별 완료 범위를 사용자가 문서에서 승인해야 한다. 임시 Enter 무시나 잠금 화면을 구현하지 않는다.
B: 원래 goal-3 전체 완료 조건을 유지하여 실제 레벨 2가 준비될 때까지 전체 완료를 보류한다. 이미 구현된 화면·실패 복귀만 검증하고 완료 범위를 제한해 보고한다.
레벨 2 맵을 R2에서 임의 생성하는 범위 확대는 이번 요청에서 금지되어 제외한다.

### 미정 항목 — 제안이지 확정 아님
모두 사람 결정이 필요하며 계획 작성은 계속하되 관련 구현 전에 결정한다.
- 동일 갱신/시간 갱신: A를 검토한다. 지연 호출에서는 400ms 기한을 순서대로 방문하여 중간 칸 충돌을 건너뛰지 않는다. 현재 시각과 같은 유령 기한을 현재 입력과 합치는 안, 이미 처리된 기한은 소급 합치지 않는 안을 제안한다. 이 때문에 생기는 콜백 순서 영향을 architect가 검토하고 사용자가 의미를 승인해야 한다.
- 시간 원천: performance.now 경과시간, 플레이 시작부터 60,000ms. blur는 눌림 해제만 하고 시간은 계속 흐르는 안을 제안한다. 백그라운드 복귀에도 경과시간을 반영하되 최초 실패 시점에서 멈춘다. 일시정지는 추가하지 않는다.
- 시간 표시: ceil(남은 ms/1000), 시작 60·양수 최소 1·정확히 0이면 0을 제안한다. 보너스는 이 표시값이 아닌 floor(실제 남은 초)×10이다.
- 실패 갱신 점수: 즉시 점등 상태는 반영하되 같은 갱신이 실패라면 신규 100점과 클리어 보너스는 지급하지 않는 안을 제안한다. 이전 점수는 실패 화면에 남고 Enter에 0이 된다. 이 지급 정책은 원 인터뷰에서 미정이므로 승인 전 사실로 취급하지 않는다.
- 타이틀 시작: 새 Enter keydown 1회로 레벨 1 시작을 제안한다. repeat는 무시하고 전환 시 눌림을 정리해 동일 누름이 다음 화면까지 번지지 않게 한다.
- 클리어 Enter: 확정 원 계약은 레벨 1→2→3이다. 없는 R3 레벨 2와의 경계는 위 A/B 선택이 필요하다. 타이틀 복귀·레벨 1 재시작·가짜 레벨 2로 바꾸지 않는다.
- 정확한 UI 문구는 R3 보류다. R2에서는 화면 의미·값·입력 역할만 합의한다. 필요한 표시용 문자열은 src/strings.js에 모으되 정확 문안 최종 승인이나 7장 완료로 취급하지 않는다. 작은 HUD의 글자 렌더링/가독성도 문서 검토 대상이다.

## In scope / out of scope
포함: 레벨 1 등불 5·유령 1·60초, 신규 점등 100점, 클리어 floor(남은 초)×10, 같은 칸/동일 갱신 맞교환 충돌, 실패 우선, 시간·점수·남은 등불 HUD, 네 화면 및 승인된 Enter, 수치 테스트·실브라우저 확인 계획.
