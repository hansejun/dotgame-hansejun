# R2 실행 전 계획 — goal-2 / goal-3

## Summary
계획만 작성한다. 이번 작업에서는 GAME_DESIGN.md·제품 소스·테스트를 수정하지 않으며 테스트·게이트·포매터·브라우저 실행을 모두 생략한다. 이 문서 저장은 구현 승인도, 사람 검토 완료도 아니다.

확인 근거: AGENTS.md, GAME_DESIGN.md v1, src/logic.js, src/main.js, src/levels.js, src/sprites.js, index.html, test/logic.test.js, test/index.js, 원 인터뷰 .gjc/_session-01a1c851-6892-733d-9f93-49c114e9c76e/specs/deep-interview-lighthouse-r0.md. 원 인터뷰의 확정 규칙과 미승인 제안을 구분했다.

현재 구현은 즉시 논리 이동·120ms 표시 보간·방향키 눌림 관리만 제공한다. isPassable은 .과 P만 허용하며 main은 방향키만 전달하고 매 프레임 그리기만 한다. 타이머 전이·점수·등불·유령·화면 상태·strings.js는 없다. 테스트는 문자 whitelist를 #.P로 제한하고 Enter 무시를 명시적으로 검증한다. index.html의 240×192/720×576 및 기존 팔레트는 보존한다.

## Intent Diff
- 현재: R1 이동 골격, 빈 HUD, 플레이 맵 직접 표시.
- goal-2: 승인된 레벨 1 격자에서 등불 5개·유령 1마리·60초·점수·HUD가 함께 작동하는 코어 루프. 승패 판정 자체도 순수 로직에 포함한다.
- goal-3: 타이틀·플레이·클리어·실패를 표시하고 승인된 Enter 전환을 연결한다. 실패 Enter는 타이틀 복귀와 점수 0을 함께 수행한다.
- 선행 변경: 다음 실행 단계에서만 GAME_DESIGN 2/3/4/5/9장을 갱신하고 사람에게 먼저 보여 준다. 7장의 정확한 UI 문구·사운드, 8장의 R3 확장, 10장의 R3 갱신을 당겨오지 않는다.
- 보존: 기존 AC-1~7의 번호·원문·R1 확인 이력. 전체 수용 기준은 최소 20개이며 아래 제안은 AC-1~30이다. R1 한정 문구는 역사적 조건이지 R2 HUD·타이틀 금지로 해석하지 않는다.

## Decision Drivers
1. AGENTS의 문서 우선 및 사람 검토 경계: 원 인터뷰는 입력 근거이고 제품 구현의 유일한 기준은 검토된 GAME_DESIGN이다.
2. 즉시 논리 이동, 400ms 왕복, 실패 우선, 정확한 점수 공식의 재현성: 화면 보간·프레임 수가 판정 기준이 되어서는 안 된다.
3. R2/R3 경계와 완성도 정직성: 레벨 2 데이터가 없는데 다음 레벨을 가짜로 만들거나 Enter를 조용히 무시한 채 goal-3 전체 완료를 선언하지 않는다.

### Principles
- 확정 수치는 그대로, 미정은 제안과 승인 필요 항목으로 표시한다.
- 상태·판정은 canvas 없는 순수 함수, 시간은 호출자가 주입한다.
- 맵의 정보는 문자 격자 하나에서 파생하며 좌표 중복 기입을 하지 않는다.
- 실패·클리어는 한 번만 확정하고 terminal 이후 시간·점수·유령을 동결한다.
- 실브라우저 사람 확인이 완료 기준이며 테스트나 fixture 캡처로 대체하지 않는다.

## Options
### 갱신 설계 비교
A. 기존 즉시 입력 전이를 확장한 트랜잭션 갱신(권고 제안): 입력 또는 시간 갱신 호출 1회를 같은 갱신으로 정의한다. 그 호출에서 미처리 유령 기한과 현재 입력을 함께 처리하고 이전/이후 논리 위치로 충돌을 판정한다. 기존 120ms 표시 전용 규칙과 잘 맞는다. 다만 콜백 순서가 갱신 경계에 영향을 줄 수 있으므로 문서에 포함 범위·시간 동률 처리 정책을 명시하고 승인받아야 한다.
B. 프레임 단위 입력 일괄 처리: 같은 프레임 내 맞교환을 설명하기 쉽지만 입력 순간 논리 위치 변경을 프레임까지 늦출 위험이 있다. 원 규칙을 깨는 단순 RAF 지연 방식은 채택하지 않는다. 원 규칙을 그대로 만족하는 별도 설계 증명이 없으면 제외한다.

### 클리어 Enter/R3 경계 비교
A. 권고: 레벨 1 클리어까지의 R2 검증과 다음 레벨 전환 계약 검증을 구분한다. 실제 다음 레벨 진입의 완료 확인은 승인된 R3 레벨 2 데이터 이후로 연기한다. 사용자가 이 단계별 완료 경계를 문서에서 명시 승인해야 한다. Enter 무시·잠금 화면을 임시 기능으로 추가하지 않는다.
B. 원래 goal-3 완료 조건을 그대로 유지한다: R3 데이터 준비 전에는 goal-3 전체 완료를 보류한다. 화면·실패 복귀 등 완료 가능한 부분은 검증하되 전체 완료로 보고하지 않는다.
C. R2로 레벨 2 맵 제작을 당겨오는 범위 확대는 이번 요청에서 금지되어 선택하지 않는다.

### 미정 항목과 결정권
아래는 v1 확정 사실이 아니라 사람 결정이 필요한 제안이다. 계획 작성은 계속하되 승인 전 구현 진입을 막는다.
- 동일 갱신/시간 처리: A를 기본안으로 검토. 지연 프레임은 400ms 경계마다 순서대로 처리하고 중간 충돌을 건너뛰지 않는다. 현재 시각과 같은 유령 기한은 현재 입력과 한 전이에 포함하는 안을 제안한다. 이미 처리한 기한을 소급 합치지는 않는다. 이 구분과 이벤트 호출 순서 영향을 사용자에게 설명하고 architect가 경계 시나리오를 점검해야 한다.
- 시간 원천: performance.now 기반 경과시간, 플레이 시작 순간부터 60,000ms. blur는 기존 눌림만 해제하고 시간을 멈추지 않는 안을 제안한다. 일시정지는 만들지 않는다. 백그라운드 복귀 때 실제 경과시간을 반영하되 이미 발생한 실패 시점에서 멈춘다. 승인 필요.
- HUD 시간: ceil(남은 ms/1000)로 시작 60, 양수면 최소 1, 정확히 0이면 0을 제안한다. 표시 반올림과 보너스 floor(남은 초)는 별개다. 승인 필요.
- 실패한 갱신의 점수: 즉시 점등 상태는 반영하되 같은 갱신 실패라면 그 갱신의 신규 100점과 클리어 보너스는 지급하지 않는 안을 제안한다. 이전 점수는 실패 화면에 남기고 실패 Enter에 0으로 만든다. 점등과 점수 지급 순서는 미정이므로 이 안을 사실로 취급하지 않는다. 사용자 결정 필요.
- 타이틀 시작: 새 Enter keydown 1회로 레벨 1을 시작하는 안. repeat는 무시하고 화면 전환 시 눌림 상태를 정리하여 같은 누름이 다음 화면까지 번지지 않게 한다. 사용자 결정 필요.
- 클리어 Enter: 원 계약은 레벨 1→2, 레벨 2→3이다. R3 미구현 경계는 위 A/B 중 사용자 결정 필요. 레벨 1 재시작·타이틀 복귀·가짜 레벨 2·최종 화면으로 대체하지 않는다.
- 정확한 UI 문구는 R3 보류를 유지한다. R2에서는 화면 종류·값·입력 의미만 합의한다. 꼭 필요한 표시용 문자열은 향후 승인된 의미를 src/strings.js 한 곳에서 관리하며 문구 최종 승인이나 7장 완성으로 취급하지 않는다. 글자 렌더링 방식·작은 HUD 가독성도 구현 전 도식 검토 대상이다.

### 레벨 1 후보 격자 — 문서 선행·사람 검토 후 채택
기존 P와 모든 # 위치를 보존하고 . 일부만 L/a로 바꾼 15×11 제안이다. L 정확히 5개, 가로로 연속한 a 5칸 경로 1개다. 정적 검토안이며 실제 플레이 검증을 실행한 격자가 아니다.

```text
###############
#P...L.......L#
#........##...#
#...##...##...#
#.L.##........#
#....aaaaa....#
#..........L..#
#......##.....#
#......##.....#
#.L...........#
###############
```

범례: # 벽, . 바닥, P 시작점(바닥), L 등불(통행 가능), a/b/c 서로 다른 유령의 직선 경로(바닥처럼 통행 가능, 경로 문자 자체는 화면에 표시하지 않음). R2 실맵에는 a만 사용한다. 가로 경로 유령은 맨 왼쪽에서 오른쪽으로, 세로 경로는 맨 위에서 아래로 출발한다. 끝에서는 다음 400ms에 반대쪽 인접 칸으로 이동하고 끝칸에서 추가 대기하지 않는 해석을 문서 검토에서 확인한다. 격자에서 경로·시작점·등불을 파생하며 별도 좌표 목록은 만들지 않는다.

## Sequencing and dependencies

- goal-2: AC-8~23 및 AC-1~7 회귀. 실제 이동·점등·순찰·시간 소진·안전 클리어를 수행하고, 정밀한 동시 충돌은 수치 테스트 결과와 실제 세션 관찰을 함께 남긴다.
- goal-3: AC-24~29 및 goal-2 회귀. 새로고침→타이틀→시작→충돌 실패→Enter 복귀→재시작, 별도로 60초 소진 실패와 안전 클리어를 확인한다. AC-30은 R3 의존으로 분리하고 확인하지 않은 항목을 체크하지 않는다.
- 증거는 실제 상태를 사용하는 실행 로그·사람 체크·실브라우저 관찰이다. fixture 스크린샷은 증거가 아니다. 완료 보고는 사람이 무엇을 열고 AC 몇 번에서 무엇을 볼지 적는다.
- Handoff: executor는 승인된 goal 하나씩 구현한다. architect는 시간/충돌 계약에, critic은 문서/범위/AC 정합성에 한정한다. 성능 실험 과제가 아니므로 autoresearch는 불필요하다. ultragoal 같은 자동 장기 실행은 미정 정책·R3 경계를 자동 승인하는 수단으로 사용하지 않는다.

## Risks and mitigations
- 콜백 순서/지연 프레임으로 판정 달라짐: 같은 갱신 정의를 문서화하고 399/400ms·0초·맞교환·중간 유령 이동을 주입 시간 테스트로 검증한다.
- 현재 테스트의 #.P whitelist·Enter 무시가 새 규칙과 충돌: 삭제로 숨기지 않고 승인된 새 계약으로 기대값을 교체하며 기존 이동·입력·불변성 검증은 유지한다.
- 맵 채택을 서두름: 본문은 후보일 뿐이며 5장 선행 변경과 사람 검토 없이는 src/levels.js에 넣지 않는다.
- 문구 R3 보류와 R2 화면 필요의 충돌: 의미/값/입력만 합의하고 정확 문구 최종화·사운드를 범위 밖으로 유지한다.
- R2 클리어 Enter가 R3 데이터에 의존: 단계별 완료 합의를 받거나 goal-3 전체 완료를 보류한다. 가짜 맵·최종 화면·임시 no-op로 봉합하지 않는다.
- 기존 확인 이력 과대 해석: R1 기록은 보존하지만 새 기능과 변경된 실제 맵은 다시 사람 확인한다. 이 계획에서 테스트·플레이를 했다는 주장은 하지 않는다.
