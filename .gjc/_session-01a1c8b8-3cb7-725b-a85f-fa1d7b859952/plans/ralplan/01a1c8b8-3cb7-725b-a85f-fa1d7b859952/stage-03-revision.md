### Principles
- 확정 수치와 사용자 결정을 구현 계약으로 옮기고 제안 맵·도트는 사람 검토 후 채택한다.
- 상태 전이는 canvas 없는 순수 함수이며 현재 시간은 외부에서 주입한다.
- 격자가 배치의 단일 원천이고 좌표 목록을 별도로 적지 않는다.
- 실패·클리어를 한 번 확정한 뒤 시간·점수·유령을 동결한다.
- 테스트와 실제 브라우저 사람 확인을 분리하고 관찰하지 않은 항목을 완료 처리하지 않는다.

## Options
### 옵션 A — 선택: 시간순 순수 전이 + 즉시 입력
입력/시간 처리 1회를 동일 갱신으로 정의한다. 현재 입력보다 이전인 유령 400ms 기한을 시간순 개별 처리하고 정확히 같은 시각의 유령 이동과 입력은 한 갱신으로 함께 판정한다. 이미 처리한 기한은 소급 병합하지 않는다. 입력 시각의 논리 이동 즉시성을 유지하면서 맞교환·중간 충돌을 검증할 수 있다. 지연 호출의 내부 하위 갱신 순서를 명시해야 한다.
### 옵션 B — 비선택: RAF 단위 입력 묶음
렌더 주기로 입력을 모으면 동시성 설명은 간단하지만 입력 순간 논리 위치 변경을 지연시켜 확정 규칙을 깨고 프레임률 의존성을 만든다. 채택하지 않는다.
### R3 연결 비교
사용자가 선택한 안은 R2 클리어 Enter no-op, 실제 다음 레벨은 R3 goal-4이다. 대안인 goal-3 전체 완료 보류는 더 이상 필요하지 않다. 레벨 1 재사용·가짜 레벨 2·최종 화면 대체는 금지한다. 이 선택을 GAME_DESIGN 3/9장에 명시해 이전 계약의 단계 경계를 분명히 한다.

## 확정된 사용자 결정
아래는 더 이상 미정 제안이 아니다.
1. 입력/시간 처리 1회가 동일 갱신이다. 현재 입력보다 과거인 400ms 기한은 시간순 개별 처리, 현재 입력과 정확히 같은 시각의 유령 이동은 함께 처리한다. 이미 처리한 기한을 소급 합치지 않는다.
2. performance.now 실제 경과시간을 사용한다. blur·백그라운드에서도 일시정지하지 않는다. blur는 기존 눌림 해제 의미를 유지한다.
3. HUD는 ceil(remainingMs/1000), 보너스는 floor(remainingMs/1000)×10. 시작 60, 60,000ms에 0 및 실패.
4. 실패 갱신의 점등은 반영하지만 해당 갱신 신규100점과 클리어 보너스는 지급하지 않는다. 이전 점수는 유지하고 실패 Enter에서 0으로 만든다.
5. 타이틀의 새 Enter는 레벨 1 시작, 플레이 Enter는 무시한다. repeat와 동일 누름의 화면간 재사용을 금지한다.
6. R2 클리어 Enter는 no-op이다. R2 goal-3은 레벨 1 클리어 화면·획득 점수까지이며 다음 레벨은 R3 goal-4다.
7. R2 3장의 최소 문구: 타이틀 '폭풍 전의 등불' / 'ENTER로 시작'; 클리어 '등불을 모두 켰다' / '점수'; 시간초과 실패 '폭풍이 왔다'; 충돌 실패 '유령에게 잡혔다'; 실패 공통 '점수' / 'ENTER로 타이틀'. 현재 지정안을 우선하고 7장 전체 정리는 R3에 남긴다.
material-open-items는 없다. 맵·도트 후보의 사람 검토와 계획 승인은 여전히 필요하며 구현 승인은 아니다.
