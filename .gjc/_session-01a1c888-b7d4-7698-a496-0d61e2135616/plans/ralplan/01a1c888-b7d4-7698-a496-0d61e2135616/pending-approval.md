## Principles

3. 키 수명은 이동 잠금과 별개로 추적하며 입력 큐·키 반복 이동은 없다.

## 구현 순서 — 전부 goal-1 내부
1. 실제 맵·스프라이트·팔레트를 옮기고 시작점·통행·경계 순수 판정을 연결한다.
2. 첫 keydown을 잠금 검사 전에 pressed로 기록한다. 이미 눌린 키나 repeat는 이동하지 않는다. 이동 중 새 누름도 기록하되 이동은 폐기, keyup은 항상 반영한다. 종료 시 held-key 재평가·예약 실행 없음. 포커스 유실은 키 기록만 정리하며 이동을 만들지 않는다.
3. 새 입력 시각에서 경과<120ms면 무시, 경과≥120ms면 새 누름 평가. 통행 성공일 때만 논리 위치를 즉시 바꾸고 출발→목표 표시 보간 시작. p=clamp((now−start)/120,0,1). 막힘은 키 기록 외 위치·애니메이션·잠금을 만들지 않으며 직후 다른 새 방향 입력 가능. rAF 종료 프레임 지연이 입력 잠금을 늘리지 않는다.
4. Canvas 렌더와 고정 크기를 연결하고 집중 테스트 후 실제 브라우저에서 사람이 AC 번호별 확인한다. 여러 실행 작업으로 나눠도 goal은 하나다. 위임 시 에이전트당 명시 파일은 최대5개, 공유 계약 생산 후 소비 순서 준수. 현재는 구현을 위임하지 않는다.

## 검증 계획
현재 테스트 성공·실제 동작을 주장하지 않는다. 향후 `node --test test/`. 읽기 전용 확인 Node v22.20.0의 기본 ESM 구문 감지를 사용하며 package.json/npm/빌드는 추가하지 않는다. 환경에서 감지가 꺼졌다면 Node 지원을 확인하고 `node --experimental-default-type=module --test test/`로 명시한다.
- AC-1: 실제 격자 일치·P 유일성/도출·바닥 통행·연결성. 사람은 실제 배치·도트·색을 기획서와 대조한다.
- AC-2/3: 네 방향·대각 없음·상태 불변성·입력시각 t 즉시 논리 목표·표시 t 출발/t+60 중간/t+120 목표 및 이후 고정·시각 위치가 판정에 영향 없음. t+119 새 입력 거부/t+120 해제 후 새 누름 허용. 정확한 시간은 눈대중으로 측정했다고 하지 않는다. 실제 브라우저 Sources breakpoint/Scope로 입력 전후 논리/표시 분리를 확인하고, 멈추지 않는 별도 실행의 DevTools logpoint로 시각·보간 진행·종료값을 관찰한다. 첫 관측 프레임이120ms 이후일 수 있음을 구분한다. 제품 디버그 기능을 넣지 않는다.
- AC-4/5: 반복 keydown/repeat, 잠금 중 다른 키 누름·유지·해제·재누름, 여러 키 교차, 큐 재생 없음, 포커스 유실 후 입력 회복. 사람은 실제 짧은/긴 누름과 이동 중 다른 키 유지 후 재누름을 확인한다.
- AC-6: 실제 외곽/내부 벽 무반응·직후 통행 방향 새 누름. 외곽이 전부 벽이므로 실제 플레이로 맵 바깥 분기를 검증했다고 주장하지 않는다. 열린 가장자리 단위 fixture로 네 방향 범위 밖 거부를 별도 검증하고 브라우저 DevTools에서 실제 logic 모듈을 import해 같은 경계 함수를 호출하여 위치·애니메이션·잠금 불변을 보조 확인한다. 실제 맵·제품 조작을 바꾸지 않는다. fixture나 그 스크린샷은 실제 플레이 완료 증거가 아니다.
- AC-7: Canvas 속성·CSS 크기·타일/HUD 오프셋·창 변경에도 고정 배율·제외 오브젝트 부재를 사람이 확인한다. CSS px와 기기 물리 px를 혼동하지 않는다.
실제 index.html을 연다. file:// 모듈 제한이면 허용된 `python3 -m http.server 8000`으로 `http://localhost:8000/index.html`을 연다. 로컬 검증용 정적 서버일 뿐 제품 백엔드가 아니다. 실제 URL/파일과 AC별 관찰·미확인을 기록한다. 자동 체크·fixture 증거 대체 없음.

## ADR
### Decision
현재 v1 기반의 최소 순수 상태 전환+Canvas 어댑터. 논리 이동 즉시, 화면만120ms, 키 수명 독립 추적.
### Drivers
범위 충실성·입력 정확성·최소 실행 구조·사람 검증.
### Alternatives considered
위 A/B/C. 임시 맵·색·캐릭터나 미래 범용 엔진은 기존 확정 기획을 대체하므로 채택하지 않는다.
### Why chosen
AGENTS의 기존 경계를 그대로 쓰며 새 기능 없이 결정적 경계 검증이 가능하다. M01/M02 재승인은 불필요하다.
### Consequences
6개 파일과 의존성0. 프레임 관측과 정확한 논리 시간을 구분해야 한다. 테스트 통과는 완료가 아니다.
### Follow-ups
현재 계획 보관. 별도 실행 승인 후 같은 goal-1 구현·집중 검증·실제 사람 AC-1~AC-7 확인. 현재 코드 변경 요청 없음.
