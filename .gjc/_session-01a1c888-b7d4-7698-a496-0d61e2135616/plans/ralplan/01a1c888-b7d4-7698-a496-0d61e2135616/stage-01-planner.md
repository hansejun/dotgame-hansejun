# R1 재계획 — goal-1: 맵 위에서 캐릭터가 한 칸씩 움직이고 벽에 막힌다

## Summary
한국어 short-mode 계획. 제품 기준은 현재 GAME_DESIGN.md v1과 AGENTS.md이며 이전 계획·인터뷰는 맥락만 제공한다. 이번 작업은 계획 저장만 한다. 제품 문서·코드 변경, 테스트·게이트·포매터 실행, 구현 위임·커밋을 하지 않는다. 아래 구현 순서는 모두 하나의 goal-1 내부 작업이며 추가 goal이 아니다. 실제 완료는 9장 AC-1~AC-7의 사람 브라우저 확인이다.

### 원칙
1. 현재 v1 수치·맵·팔레트를 그대로 구현하고 과거 보류를 부활시키지 않는다.
2. 입력 순간의 논리 위치와 120ms 시각 보간을 분리한다.
3. 누름·해제 수명을 잠금과 무관하게 추적하고 입력을 예약하지 않는다.
4. 의존성 없는 최소 모듈과 순수 테스트를 사용하되 테스트 성공을 사람 완료로 대체하지 않는다.

## Intent Diff
- M01 해결: 4장 도트 설명·5장 실제 레벨 1 격자·6장 팔레트가 현재 기준이다. 설명을 16×16 팔레트 인덱스 배열로 옮기는 것은 구현이며 새 디자인 승인이나 문서 편집 선행조건을 만들지 않는다.
- M02 해결: 2장에 벽·맵 바깥 입력은 위치 불변, 애니메이션·입력 잠금·소리·흔들림 없음으로 확정됐다.
- 이전 계획의 문서 보완·미정값 승인 대기와 R1-C 식별자는 폐기하고 현재 9장 AC-1~AC-7을 사용한다. 과거 인터뷰의 등불·유령·HUD 값은 가져오지 않는다.

## Decision Drivers — 상위 3개
1. v1과 정확히 같은 단일 목표·수치·시각 자산.
2. 즉시 논리 이동, 120ms 보간, held-key 수명 및 막힘 처리의 정확성.
3. package.json·의존성·빌드 없이 실행하고 실제 브라우저에서 사람이 확인 가능한 최소 구조.

## In scope / out of scope
포함: 레벨 1의 #·.·P, P 아래 바닥 유지, 정면 고정 등대지기 도트, 바닥·벽, 8색 팔레트, 방향키 4개, 통행·막힘·경계, 즉시 논리 이동과 120ms 표시 보간, 입력 수명, 고정 배율 및 비어 있는 상단 16px 공간.
제외: R2/R3의 등불·유령·점수·타이머·승패·화면 전환·다른 레벨·저장, HUD 게임 값·문구, 효과음·흔들림·조명, Enter 기능·추가 조작, 외부 자산·의존성·서버 제품 기능. 반응형 확대 없음. UI 문자열이 없으므로 빈 src/strings.js도 만들지 않는다. GAME_DESIGN.md·AGENTS.md는 수정하지 않는다.

## File-level changes — 향후 구현 책임, 최대 6개 파일
- index.html: Canvas 240×192, 표시 720×576의 고정 CSS, 픽셀 선명도 유지, ES module 진입점. 상단 16px는 팔레트 배경만 두고 텍스트·게임 값 없음.
- src/levels.js: 5장 15×11 문자 격자를 그대로 복사. 유일한 P에서 시작 위치를 도출하고 지형은 바닥으로 취급한다. 별도 시작 좌표 상수 없음.
- src/sprites.js: 6장의 8색 hex와 4장 설명에 맞춘 16×16 팔레트 인덱스 배열. 등대지기 바깥 픽셀은 그리지 않아 바닥이 보이게 한다. 투명 처리는 아홉 번째 색이 아니다. 이미지 파일 없음.
- src/logic.js: DOM·Canvas·내부 시계 없는 순수 상태 변환. 상태와 이벤트/시각을 받아 새 상태 반환. 논리 좌표, pressed 방향키 집합, 애니메이션 출발/목표/시작 시각, 통행·경계 판정 및 보간값 계산을 책임진다.
- src/main.js: 방향키 keydown/keyup 정규화, 관련 기본 스크롤 억제, performance.now()의 단일 시간축 전달, requestAnimationFrame 표시. 보간 좌표만 Canvas에 그리며 충돌은 논리 좌표로만 처리한다. 내부 상태는 이 모듈에서 관리하며 전역 디버그 API나 제품 디버그 UI를 추가하지 않는다.
- test/logic.test.js: node:test·node:assert/strict만 사용하는 순수 로직·맵·시간/입력 수명 테스트. 테스트용 작은 맵은 단위 테스트 전용이며 실제 브라우저 완료 증거가 아니다.

## Sequencing and dependencies
1. **데이터·판정 기반:** levels/sprites에 v1을 옮기고 문자 격자·P·색·도트·통행/경계 순수 판정을 만든다. 기대값은 기획에서 취한다.
2. **입력·시간 전환:** 첫 keydown이면 잠금 검사보다 먼저 해당 키를 pressed에 기록한다. 이미 pressed이거나 repeat=true이면 이동하지 않는다. 애니메이션 중 새 누름도 기록하되 이동은 폐기한다. keyup은 애니메이션 중에도 반드시 pressed에서 제거한다. 이렇게 잠금 중 누른 키를 계속 유지해도 종료 후 자동 이동하지 않으며 해제·재누름해야 움직인다. 입력 큐·종료 시 held-key 재평가 없음. 브라우저 포커스 유실 시 pressed를 정리해 해제 이벤트 누락으로 영구 고착되지 않게 하되 새 이동은 만들지 않는다.
3. **이동/표시 연결:** 새 누름 시 입력 시각 t를 기준으로 현재 애니메이션의 경과를 먼저 판정한다. 경과<120ms면 입력 폐기, 경과≥120ms면 새 누름 평가 가능. 통행 가능하면 논리 좌표를 즉시 목표로 바꾸고 이전 좌표→목표의 표시 보간만 시작한다. p=clamp((now−t)/120,0,1); 60ms는 중간, 120ms 이상은 정확한 목표. 벽/범위 밖이면 pressed 기록 외 위치·애니메이션·잠금 상태를 만들지 않는다. 직후 다른 통행 방향을 새로 누르면 즉시 이동할 수 있다. main의 rAF가 아직 종료 프레임을 그리지 않았어도 입력 시각으로 잠금 종료를 판정한다.
4. **단일 목표 검증·인계:** 아래 순수 테스트와 실제 파일 브라우저 확인을 수행한다. 이 순서의 각 항목은 별도 goal이나 커밋 단위가 아니다. 구현 승인 후 executor 한 명이 6개 파일 범위로 수행하면 충분하며 architect/critic은 입력 수명·시간 경계·범위 검토에 한정한다. autoresearch나 ultragoal은 필요하지 않고 사람 완료를 대체할 수 없다.

## Verification — 향후 실행 명령과 환경
현재는 어떤 테스트·게이트·포매터·브라우저 검증도 실행하지 않았다.
- 향후 순수 테스트: `node --test test/`. 0-Main이 현재 환경을 읽기 전용 확인해 Node v22.20.0임을 전달했다. 이 버전의 기본 ESM 구문 감지가 package.json 없는 .js의 import/export를 처리하므로 package.json·npm·확장자 변경 없이 위 명령을 사용한다. 이번 계획에서 테스트 실행 성공을 주장하지 않는다. 다른 환경에서 감지가 꺼진 경우 설치 Node의 지원을 확인하고 `node --experimental-default-type=module --test test/`로 명시할 수 있으나 패키지 파일을 추가하지 않는다.
- 브라우저는 실제 index.html을 연다. file://의 ES module/CORS 제한이면 AGENTS가 허용한 `python3 -m http.server 8000`으로 같은 디렉터리를 제공하고 `http://localhost:8000/index.html`을 연다. 이는 로컬 확인용 정적 서버이며 제품 백엔드가 아니다.

## Escalation/Risk Gate
현재 M01/M02는 차단 요인이 아니다. 문서 편집·재디자인 승인을 선행시키지 않는다. 향후 실제 v1 모순이나 범위·수치 변경이 필요할 때만 구현을 멈추고 구체 충돌을 사람에게 알린다. 같은 실패 시도는 6번을 넘기지 않고 막힌 지점과 재현을 보고한다. 자동 검증 통과 후에도 AC-1~AC-7의 실제 사람 확인 전에는 goal-1 완료를 선언하지 않는다.

## Verification Plan — 테스트와 사람 확인의 구분
- **AC-1:** 순수 테스트로 15×11, #·.·P만 사용, P 유일성·시작점 추출·P의 바닥 통행, 바닥 연결성 및 실제 격자 일치를 검사한다. 사람은 실제 맵 배치와 정면 캐릭터·바닥·벽 도트 및 팔레트를 비교한다.
- **AC-2/3:** 네 방향 통행과 대각 이동 없음, 입력 상태 비변이, 수락 시각 t 즉시 논리 목표, 표시 t=출발/t+60=중간/t+120=목표 및 이후 고정, 표시 좌표가 통행 판정에 영향을 주지 않음을 시간 주입 테스트한다. t+119의 새 입력 거부와 t+120의 해제 후 새 누름 수락을 검사한다. 사람은 브라우저에서 한 칸 이동·목표 정렬을 본다. 정확한 즉시 논리 변경과 120ms는 눈대중으로 측정했다고 주장하지 않는다. 실제 모듈을 DevTools Sources에서 열어 keydown 처리 전후 breakpoint/Scope로 논리 좌표가 렌더 전에 바뀌고 출발 표시값은 남아 있음을 확인한다. 정확한 시간은 breakpoint로 실행을 멈추지 않는 별도 실행에서 DevTools logpoint로 수락 시각·프레임 시각·보간 진행도와 종료값을 관찰한다. 종료 분기 120ms와 rAF의 첫 관측 프레임 시각이 120ms 이상일 수 있음을 구분한다. 별도 debug UI·전역 상태 노출·제품 로그 코드는 추가하지 않는다.
- **AC-4/5:** held-key 반복 keydown·repeat=true, 잠금 중 다른 키 누름/유지, 잠금 중 keyup, 해제·재누름, 여러 키 교차와 종료 후 큐 재생 없음, 포커스 유실 후 입력 회복을 검사한다. 사람도 짧은 누름·긴 누름·이동 중 다른 방향 유지·해제 후 재누름을 실제 브라우저에서 반복해 확인한다.
- **AC-6:** 실제 맵의 외곽 벽과 내부 벽 모두 막힘·상태 불변 및 바로 다른 새 방향 이동을 검사한다. 실제 레벨은 외곽 전체가 벽이므로 그것만으로 맵 바깥 좌표 분기를 검증했다고 하지 않는다. 별도 순수 테스트의 열린 가장자리 작은 맵에서 네 방향 음수/폭·높이 초과 좌표를 만들어 범위 검사와 즉시 후속 이동을 검증한다. 사람은 실제 맵에서 벽 무반응·직후 통행 방향 이동을 보고, 바깥 분기는 DevTools에서 실제 logic 모듈 함수를 동적 import하여 테스트용 열린 가장자리 상태로 호출하고 위치·애니메이션·잠금 불변을 확인한다. 실제 맵을 바꾸거나 바깥 이동용 제품 조작을 추가하지 않는다.
- **AC-7:** 사람은 Canvas width/height 속성 240×192, DevTools의 표시 크기 720×576, 타일 16px·상단 공간 16px와 창 크기 변경 시 고정 배율을 확인한다. HUD 값·문구·등불·유령·전환·소리가 없는지 함께 확인한다. CSS 픽셀 크기와 기기 물리 픽셀을 혼동하지 않는다.
- 완료 인계는 사람이 연 실제 URL/파일, AC 번호별 관찰 및 미확인 항목을 명시한다. 테스트 fixture 화면이나 자동 스크린샷만으로 사람 확인을 채우지 않으며 제품 문서에 체크 표시를 자동 기입하지 않는다.

## Risks and mitigations
- 잠금부터 검사하면 잠금 중 누른 키가 종료 후 새 누름으로 오인됨 → pressed 기록을 먼저 하고 keyup은 항상 처리한다.
- 막힘에서 120ms 잠금을 생성하는 실수 → 통행 성공에만 애니메이션 생성, blocked 직후 다른 키 입력 테스트.
- 프레임 지연을 논리 지연으로 오인 → 입력 시각으로 종료 여부를 판정하고 pure 시간 테스트와 DevTools 관측을 분리한다.
- 외곽 벽 테스트를 out-of-bounds 테스트로 오인 → 실제 격자 벽 검증과 열린 경계 fixture 검증을 구분한다.
- 과거 보류·미래 기능 유입 → v1 2/4/5/6/9장 및 6개 파일 상한으로 검토한다.
- ESM 로컬 실행 차이 → 확인된 Node 버전의 구문 감지와 기존 정적 서버 경로 사용; 의존성·package.json으로 우회하지 않는다.

## ADR
**결정:** 현재 v1을 그대로 사용하는 최소 순수 상태 전환 + Canvas 어댑터 구조를 채택한다. 논리 이동은 즉시, 시각 보간만 120ms이며 입력 수명은 애니메이션과 독립적으로 추적한다.
**근거:** 상위 3개 driver와 AGENTS의 기존 책임 경계를 모두 만족한다. M01/M02는 해결됐으므로 문서 수정이나 디자인 재승인 대기를 추가하지 않는다.
**대안:** main 단일 집중 구조와 지연 논리/입력 예약은 위 Options의 계약 위반 때문에 기각한다.
**결과:** 최대 6개 파일, 외부 의존성 0, UI 문자열 모듈 없음. 결정적 순수 검증을 얻지만 프레임 관측은 브라우저 스케줄링과 구분해야 하며 최종 완료는 사람의 AC-1~AC-7 확인에 남는다.
