`levels`의 각 정의는 승인 격자와 제한 ms만 가진다. 등불·유령 수와 시작 위치는 격자 파싱으로 얻는다. 상태의 levelIndex/score를 전이에 포함하고 main은 활성 격자를 그린다. goal-5에서 audio/storage를 각각 작고 독립적인 브라우저 모듈로 두고 main의 단일 dispatch 전후 상태를 비교해 호출한다.

### B — 실행 가능한 비채택: 순수 레벨 reducer + 별도 순수 campaign reducer
기존 레벨 로직은 레벨 상태만 계산하고 campaign reducer가 activeLevel/누적점수/화면을 관리한다. main은 중첩 상태를 렌더링한다.

두 접근 모두 의도 충족 가능하다. A를 권고하며 기존 단일 레벨 API를 호환용 별칭/폴백으로 남기지 않는다. 격자를 바꾸지 않고 함수명·인자 형태를 구현 중 단순화하는 것은 허용하되 계약 변경은 재승인 대상이다.

## Risks and mitigations
- 기존 fixed duration을 remaining 계산과 catch-up deadline 중 한쪽만 바꾸는 위험: 동일 레벨 정의를 양쪽에 적용하고 시작시각 비영점 경계 테스트.
- 전이 직후 main이 이전 맵을 그리는 위험: 상태의 levelIndex로 렌더·전이 입력을 일치시키고 레벨2/3 실제 맵 확인.
- score 차이로 음향을 고르면 보너스를 등불로 오인: 신규 lit 차이와 terminal 진입을 사용, terminal 우선 한 종류. keyup/repeat/Enter/blur가 발견한 terminal도 억제하지 않는다.
- 매 RAF 최고점 쓰기/최종음 반복: dispatch 한 곳에서 이전 playing→terminal 엣지로 한정. 화면 렌더는 부작용 없음.
- 브라우저 정책으로 resume/저장 실패: 예외 흡수·무음/메모리 fallback만, 새 기능/UI 없음. 실패 환경은 별도 관측.
- 맵을 어려워 보이게 하려 임의 벽/난이도 추가: 최소 격자로 기존 벽을 보존하고 안전 우회로 제공. 난이도 상승 요구를 추측하지 않는다.

# 폭풍 전의 등불 — 기획서 v3 (사람 승인 대기 제안)

이 문서는 v3 제안이다. R0의 합의 규칙과 R1/R2의 승인·확인 이력은 보존한다. **새 R3 배치·효과음·UI·기술·저장·최종 전이·AC는 전부 제안이며 사람 승인 전 구현하지 않는다.** v2는 goal-2·goal-3 구현과 AC-8~32 사람 확인 및 AC-1~7 이동 회귀 확인을 마친 기존 기준이다. 새 확인을 주장하지 않는다.

## 1 한 줄 콘셉트
등대지기가 폭풍이 오기 전에 바다 유령을 피해 꺼진 등불을 모두 켠다.

## 2 규칙(이동·점수)
| 항목 | 규칙 |
|---|---|
| 조작 | 방향키 4개로 상하좌우, Enter로 명시된 화면 전환만 |
| 이동 단위 | 새 방향키 한 번 누름에 정확히1칸, 대각 없음 |
| 한 칸 이동 | 논리 위치는 입력 순간 목표 칸으로 즉시 변경. 120ms는 화면 애니메이션만 |
| 이동 중 입력 | 120ms 동안 이동 입력 무시, 대기열/자동 재실행 없음 |
| 반복 | held/repeat 이동 없음. 해제 후 새 누름 필요 |
| 판정 | 화면 보간 위치가 아닌 칸 단위 논리 위치 |
| 벽/맵밖 | 이동·새 애니메이션·입력 잠금·소리·흔들림 없음 |
| 타일/맵 | 16×16px, 15×11칸 |
| HUD | 맵 위16px 한 줄: 시간·점수·남은 등불 |
| 캔버스/표시 | 논리240×192px, CSS3배고정720×576px. 반응형 없음 |

등불 논리 접촉 즉시 점등, 새 등불100점, 재방문0점. 레벨별 등불/유령/시간은 다음과 같으며 맵 배치만 R3 신규 제안이다.
| 레벨 | 등불 | 유령 | 제한 |
|---|---:|---:|---:|
| 1 | 5 | 1 | 60초=60000ms |
| 2 | 7 | 2 | 75초=75000ms |
| 3 | 9 | 3 | 90초=90000ms |
유령은 자기 직선 경로를400ms마다1칸 왕복. 가로 맨왼쪽→오른쪽, 세로 맨위→아래로 출발. 끝 도착 때 방향 반전, 다음400ms에 인접칸으로 이동하여 추가 대기 없음. 추적·벽통과·이동보간 없음. 모든 유령은 레벨 시작+400ms부터 같은 기한으로 이동하며 서로 다른 경로에 머문다.

같은 논리 칸 또는 동일 갱신 맞교환은 즉시 실패. 모든 등불 점등은 즉시 클리어, 귀환 조건 없음. 같은 갱신에 실패와 마지막 점등이 겹치면 실패 우선, 시간0+충돌이면 시간 소진 원인. 실패한 갱신도 점등은 반영하되 해당 신규100점·클리어 보너스는 지급하지 않으며 이전 누적은 유지한다.

보너스는 `floor(remainingMs/1000)×10`을 클리어 확정 시 딱1회. HUD 시간은 `ceil(remainingMs/1000)`, 양수 최소1,0이면0. 레벨1→2→3 점수 누적, 레벨 진입은 이전 보너스를 다시 더하지 않는다. 총 등불2100점, 이론상 시간보너스 상한2250점이므로 총점은0~4350 정수다(상한 달성 가능을 뜻하지 않음). 점수는 승패에 영향 없음. 실패/최종에서 title 복귀 시 현재점수0, 최고점은 별도 유지한다.

입력 또는 시간 처리1회가 동일 갱신이다. 입력시각보다 이전인 미처리 유령기한/시간소진을 시간순 개별 처리, 최초 terminal에서 중단. 정확히 입력시각과 같은 유령 기한은 입력과 함께 이전/이후 위치로 판정한다. 다중 유령은 그 기한에 전원 이동한 뒤 모든 충돌을 판정, 먼저 배열에 있는 유령만 검사하지 않는다. 이미 처리한 기한은 재처리/소급병합하지 않는다.

외부 `performance.now()`를 순수 로직에 주입. 레벨 진입 시각부터 각 제한시간이 시작한다. 클리어 화면 대기는 다음레벨 시간에 포함되지 않는다. 포커스 유실·백그라운드에서도 시간은 진행, blur는 눌림만 정리한다. 지연 호출은 중간 충돌/timeout을 건너뛰지 않는다. terminal 뒤 위치·시간·유령·점수·보너스 동결, 입력 눌림 수명 정리만 허용한다.

## 3 화면 흐름
신규 R3 전이는 아래 제안이다. 타이틀에서 새 Enter로 레벨1의 P·미점등5·유령시작·시간60·점수0·animation없음 상태로 시작한다. Enter 자동반복은 무시하며 화면을 바꾼 같은 누름을 다음 화면에서 재사용하지 않는다. 새 레벨도 방향키 눌림/animation/등불/유령/기한을 초기화하되 누적 점수만 유지한다.

| 화면 | 표시 | 새 Enter | 방향키/시간 |
|---|---|---|---|
| 타이틀 | 폭풍 전의 등불 / ENTER로 시작; goal5부터 최고 점수 N | 레벨1 새게임 | 정지 |
| 플레이 | 활성 레벨 격자 + 시간·누적점수·미점등 HUD | 무시(실제시간 판정은 진행) | 2장 적용 |
| 레벨1/2 클리어 | 등불을 모두 켰다 / 점수 N / ENTER로 다음 레벨 | 다음 레벨, 점수유지, 시계새시작 | 동결 |
| 레벨3 클리어(goal4에만 존재) | 등불을 모두 켰다 / 점수 N | 무동작 | 동결 |
| 실패 | 폭풍이 왔다 또는 유령에게 잡혔다 / 점수 N / ENTER로 타이틀 | 점수0 타이틀 | 동결 |
| 최종(goal5부터) | 모든 등불을 켰다 / 점수 N / 최고 점수 B / ENTER로 타이틀 | 점수0 타이틀, 최고점유지 | 동결 |

goal4는 레벨3 안전클리어까지이며 기존 클리어 화면을 그대로 동결한다. final·소리·저장을 선행 구현하지 않는다. goal4 사람이 확인/승인한 뒤 goal5에서 레벨3 마지막 점등의 보너스까지 확정한 같은 전이로 즉시 final로 간다. 별도 Enter·지연·추가 중간화면은 없다. final에서 Enter 한 번은 title까지만, 재시작은 해제 후 새 Enter가 필요하다. 실패도 어느 레벨이든 title0으로 돌아가며 이어하기는 없다.

## 4 오브젝트
기존 승인 도트/팔레트를 재사용한다. 모양 설명/인덱스는 기존 에이전트 제안을 사람이 승인한 이력이며 R3에 새 그림을 만들지 않는다.
| 오브젝트 | 문자/상태 | 통행 | 16×16 도트 | 인덱스 |
|---|---|---|---|---|
| 등대지기 | P | 시작 지형은 바닥 | 정면 고정, 짙은 모자/장화, 살구색 얼굴, 황토 우비, 밝은 단추. 바깥 투명 | 0·4·5·6 |
| 바닥 | . | 가능 | 어두운 청색/짙은 가로 물결, 고정 | 0·1 |
| 벽 | # | 불가 | 청회 돌, 밝은 윗면/짙은 아랫면·돌틈 | 0·1·2·3 |
| 꺼진등불 | L | 가능 | 청회 테두리/어두운 중심 | 0·2·3 |
| 켜진등불 | L 점등 | 가능 | 황토 테두리/밝은 중심, 도트밖 빛없음 | 0·5·6 |
| 바다유령 | a/b/c 각각1마리 | 경로가능/유령접촉실패 | 옅은청록 몸체, 짙은눈/윤곽, 고정 | 0·7 |
P에서 떠나도 바닥은 남는다. a/b/c 문자는 화면에 그리지 않는다. 여러 유령은 같은 스프라이트를 사용한다.

## 5 레벨 맵
모든 배치는 아래 격자만 원천으로 사용한다. `#`벽, `.`바닥, `P`시작점1개, `L`등불, `a/b/c`각각 다른 유령 경로. L/P/a/b/c는 통행 가능. 경로는 길이2이상·한 행 또는 한 열의 끊김없는 직선, 서로 겹치지 않음. 좌표를 별도 데이터로 작성하지 않는다. 외곽벽·모든 통행칸 연결을 유지한다.

```text
#........##...#
#...##...##...#
#.L.##........#
#....aaaaa....#
#..........L..#
#......##.....#
#......##.....#

###############
```

```text
#L..##...##...#
```

세 경로는 가로이며 a5칸 왕복주기3200ms, b3칸1600ms, c4칸2400ms. L은 모든 경로 밖이므로 마지막L+유령충돌 동시사건을 실맵 필수 사람 재현으로 요구하지 않는다. 수치 테스트 합성 상태에서만 증명한다.

안전 클리어 가능성의 설계 근거(좌표 데이터가 아닌 사람 이동 안내): P에서 윗변 통로를 오른쪽 끝까지 가며 위쪽 L을 켠다. 오른쪽 바깥 통로를 내려가며 아래쪽 L과 중간행의 L을 향해 짧게 왼쪽 왕복한다. 아랫변 통로를 왼쪽 끝까지 가며 L을 켠 뒤 왼쪽 바깥 통로로 올라와 왼쪽 L/한 칸 안쪽 L을 켠다. 이 순회는 a/b/c를 밟을 필요가 없고 세 맵의 모든 L에 도달한다. 자동 검사와 실제 사람 플레이로 확인하기 전 달성 증거로 간주하지 않는다.

## 7 사운드·UI 텍스트
이 장의 신규 내용은 R3 미승인 제안이다. 모든 표시 문자열/템플릿은 src/strings.js 한곳에만 둔다. 표에 없는 새 문구·새 조작 안내·알림은 만들지 않는다. N은 현재 누적점수, B는 세션 최고점(8장), T는올림초, R은미점등수다.

### 전체 UI 문자열 표
| 용도 | 정확한 문자열/템플릿 | 적용 |
|---|---|---|
| 타이틀 제목 | 폭풍 전의 등불 | title |
| 시작 | ENTER로 시작 | title |
| HUD | 시간 {T}   점수 {N}   등불 {R} | playing, 기존3칸 공백 구분 |
| 중간/goal4마지막 클리어 | 등불을 모두 켰다 | cleared |
| 점수 | 점수 {N} | cleared/failed/final |
| 다음레벨 | ENTER로 다음 레벨 | goal4부터 level1/2 cleared만 |
| 시간실패 | 폭풍이 왔다 | timeout failed |
| 충돌실패 | 유령에게 잡혔다 | collision failed |
| 복귀 | ENTER로 타이틀 | failed, goal5 final |
| 전체완료 | 모든 등불을 켰다 | goal5 final만 |
| 최고점수 | 최고 점수 {B} | goal5 title/final만 |
제목/점수/최고점/힌트는 각각 한 줄, 가운데 정렬, 한 화면 최대4줄. 기존240×192 안에 각 줄16px 마스크, 줄간격32px. 2줄 top64px,3/4줄 top48px를 사용해 마지막 줄이160px를 넘지 않는다. HUD는기존10px 글자, 나머지14px와팔레트6. 새로운 레벨번호 HUD/팝업/최고기록 축하문구 없음.

### 합성 효과음 전체 표 (goal5 전용 제안)
Web Audio API의 oscillator와 gain만 사용. AudioContext는최대1개, master gain0.10, 각 음은 시작0→5ms선형attack→지정길이끝0 선형release, 지정끝에stop/disconnect. 아래 길이는 음 하나의 전체길이이며 연속음은 빈틈없이 순서대로 재생한다. 재생속도/랜덤변조/외부파일/BGM 없음.
| 사건 | 파형 | 주파수 순서 | 음별 길이 | 전체길이 | 발화 조건 |
|---|---|---|---|---|---|
| 새 등불 | sine | 880Hz | 80ms | 80ms | 아직 playing인 갱신에서 신규점등1회 |
| 레벨1/2 클리어 | sine | 660→880Hz | 각80ms | 160ms | playing→cleared 최초1회 |
| 실패 | triangle | 220→110Hz | 각100ms | 200ms | playing→failed 최초1회, 원인관계없이 같음 |
| 전체완료 | sine | 660→880→1100Hz | 각100ms | 300ms | level3 playing→final 최초1회 |
우선순위는 failed > final > cleared > 신규등불. 마지막L은등불소리와결과음을겹치지 않고 결과음 하나만. 실패갱신 점등은등불소리 없음. 벽/재방문/이동만/유령만/Enter화면전환/타이틀진입/keyup/반복/blur/terminal대기는、その入力自体からは音を出さない。즉 해당 입력 자체의 별도 효과음이 없다는 뜻이며 **keyup/repeat/Enter/blur/RAF 등 어떤 dispatch가 지연된 최초 terminal을 발견해도 새 terminal 효과가 우선**한다. 오디오가 사용 가능한 상태이면 해당 결과음을 정확히1회 재생한다. 이미 terminal인 상태의 후속 입력/시간은 결과음을 다시 내지 않는다. 새 사건 재생 때 이전 짧은 효과음은stop해 겹침/노드누적을막는다.

자동재생하지 않는다. 최초 title 시작의 실제 새 Enter keydown 사용자 제스처에서만 AudioContext를 지연생성/resume한다. 후속 실제 승인된 Enter 화면전환에서 suspended이면resume 재시도할 수 있다. repeat/합성 이벤트/RAF만으로 활성화하지 않는다. resume은 비동기이며 게임은 기다리지 않는다. 지원안됨/생성실패/resume거절/아직suspended이면해당음은버리고 나중에재생할큐를남기지않는다. 소리실패는승패/시간/점수에영향없다. 오디오설정/음소거버튼은범위밖이다.

## 8 기술 스펙
이 장의 신규 상세는 R3 미승인 제안이다.
- HTML+Canvas2D+JavaScript ES modules, 빌드/의존성0. index.html은정적 HTTP/HTTPS로 제공한다. **필수 사람 검증은 `python3 -m http.server 8000` 후 `http://localhost:8000/`의 실제 브라우저**다. 이미 제공되는 해당저장소GitHub Pages HTTPS URL이 있을 때만 선택적·비게이팅 보조 확인을 한다. 없으면 Pages/교차origin 확인은 deferred(환경 없음)로 기록하고 로컬 수용을 막지 않는다. 배포/설정/커밋/푸시를 요구하거나 수행하지 않는다. file:// 직접열기는ES module CORS제한때문에지원실행경로가아니다. 정적서빙은게임서버/백엔드추가가아니다.
- src/logic.js는Canvas/DOM/AudioContext/localStorage/내부clock없이 상태와입력/외부now를받아새상태만반환. 모든시간계산에활성레벨duration을사용. 레벨정의는src/levels.js의5장격자원문과60000/75000/90000만. 오브젝트좌표/개수는격자에서파싱, 별도좌표테이블없음.
- src/main.js는입력/RAF/blur의단일dispatch와그리기·브라우저효과연결. 렌더자체는소리/저장부작용을내지않음. strings는UI단일원천, sprites는기존팔레트인덱스16×16배열. 상대경로import로Pages하위경로지원.
