# R1 단일 목표 계획 — RALPLAN-DR 단축형

## [S01] 요약
목표는 정확히 하나다: **맵 위에서 캐릭터가 한 칸씩 움직인다.** 이번 산출물은 계획과 승인 경계뿐이며 제품 코드·기획 문서를 변경하지 않는다. 선택안은 사용자 검토로 디자인 선행조건을 해소한 뒤에만 진행하는 최소 이동 골격이다. 이 계획의 합의는 미정 디자인 승인이나 구현 착수 승인이 아니다.

### 원칙 4개
1. 현재 GAME_DESIGN.md가 유일한 제품 기준이다. AGENTS.md의 작업·완료 제약을 지키며 과거 인터뷰의 미래 기능을 끌어오지 않는다.
2. 입력 순간 논리 이동과 120ms 화면 애니메이션을 분리한다.
3. 한 번 누름 한 칸, 애니메이션 중 입력 폐기, 누르고 있기 반복 금지를 함께 보장한다.
4. 미정 디자인·완료 계약은 사용자 검토 후 문서로 먼저 확정한다. 테스트 성공이나 계획 승인을 구현·완료 승인으로 대신하지 않는다.

## [S02] 의도 차이 / Intent Diff
- 유지: 단일 이동 목표, 2장의 확정 수치, 4·5·6장의 R1 디자인 선행조건, 외부 의존성 없는 브라우저 실행.
- 추가 제안: 논리/시각 상태 분리, 미래 파일별 책임, 검증 시나리오. 구현 구조 제안이지 새로운 게임 규칙이 아니다.
- 미승인 M01: 등대지기·바닥·벽 도트 표현과 팔레트 인덱스 배열, 레벨 1 문자 격자와 시작점·벽 배치, 8색 hex는 사용자가 검토할 별도 디자인 결정이다. 이 계획은 구체 배열·맵·색값을 제시하거나 확정하지 않는다.
- 미승인 M02: 벽에 막힌 입력의 피드백·애니메이션 여부·잠금 적용 여부를 사용자에게 확인하고 기획에 명시해야 한다. 지도 경계 처리도 승인 맵의 외곽 구조와 함께 확인한다. 막힌 이동을 정상 이동과 동일한 잠금으로 볼지, 즉시 재입력을 허용할지 여기서 선택하지 않는다.
- 중요 의도 항목 M03: AGENTS.md는 9장 번호 수용 기준과 사람의 브라우저 확인을 goal 완료 조건으로 요구하지만 v0 9장은 R2 작성을 명시한다. 과거 인터뷰 역시 R1 번호 기준을 요구하지만 현재 v0의 유예를 덮어쓸 수 없다. 사용자가 ① R1 최소 번호 기준을 9장에 먼저 넣도록 유예 범위를 조정할지, ② 9장 R2 유예를 유지하면서 R1 완료 계약의 명시적 예외를 승인할지 결정해야 한다. 권고는 ①의 최소 조정이며 **아직 승인되지 않았다**. 20항목 확장이나 R2 기능 기준을 지금 작성하지 않는다. 합의 전 구현 착수·goal 완료 선언을 보류한다.
- 승인 분리: 계획 방향 합의 → M01~M03 사용자 결정 및 별도 문서 변경 승인·검토 → 갱신된 기획에 대한 R1 구현 착수 승인 → 구현/검증 → 사람의 완료 확인. 각 승인은 다음 승인을 함축하지 않는다.

## [S03] 결정 동인 / Decision Drivers — 상위 3개
1. 의도 충실성: 확정 이동 수치만 보존하고 미정 디자인·미래 gameplay를 승인 없이 넣지 않는다.
2. 입력 정확성: 즉시 논리 이동과 120ms 시각 보간, 입력 폐기·키 반복 억제를 순수 로직으로 검증 가능하게 한다.
3. 최소 실행·검증 비용: 빌드·의존성 없이 작은 모듈로 만들고 실제 브라우저에서 사람이 확인할 수 있어야 한다.

## [S07] 미래 파일별 책임 / File-level changes
아래는 향후 별도 승인 이후의 책임 제안이며 현재 파일을 만들거나 수정하지 않는다.
- GAME_DESIGN.md: 사용자 디자인 승인 후에만 4장 도트 표현·5장 레벨 1 문자 격자·6장 8색 hex, 막힘 규칙 명시. 9장은 M03 결정에 따른 최소 변경만 별도 승인한다.
- AGENTS.md: 기본 변경 없음. M03에서 완료 계약 예외를 택해 변경이 필요하면 명시적 별도 승인 없이는 고치지 않는다.
- index.html: Canvas 진입점과 ES module 연결, 논리 크기·CSS 고정 확대. 화면 메뉴나 HUD 게임 값 없음.
- src/logic.js: Canvas/DOM 없는 순수 함수. 논리 좌표·애니메이션 시간 상태·입력 잠금/누름 상태 전환, 통행 판정. 시각 보간 결과로 충돌 판정하지 않음. 시간과 입력을 인자로 받고 내부에서 시계 조회·타이머 실행하지 않음.
- src/levels.js: 승인된 5장 문자 격자 그대로 복사, P 등 승인 범례로 시작점을 도출. 시작 좌표의 별도 상수·미승인 맵 없음.
- src/sprites.js: 승인된 8색 hex 팔레트와 팔레트 인덱스 배열. 외부 이미지 없음.
- src/main.js: DOM 키 이벤트를 순수 로직 입력으로 전달하고 requestAnimationFrame으로 Canvas 렌더링. 키 해제와 새 누름 구분, event.repeat 차단, 필요 방향키 기본 스크롤 억제. 애니메이션 중 입력을 나중에 실행하도록 저장하지 않음.
- test/logic.test.js: node:test 기반 순수 상태 전이·입력·경계 검증. 승인 디자인을 따르는 통행성 사례.
- src/strings.js: R1에 사용자 UI 문구가 없으므로 만들지 않는다. 추후 승인된 문구가 필요할 때만 AGENTS 규칙에 따라 한곳에 둔다.

## [S08] 의존 순서 / Sequencing and dependencies
1. 현재 문서 근거와 단일 목표의 계획 방향을 검토한다. architect/critic은 S02의 충돌·미정 사항, S05 범위, S09 기준만 검토하고 구현하지 않는다. stage 1 원본은 의도 조정 전 불변 검토 기준이다.
2. 사용자에게 M01 디자인안, M02 막힘 처리 선택지, M03 완료 계약 조정안을 서로 구분하여 검토받는다. 구체 맵·팔레트·배열은 이 계획의 빈칸을 임의 채우지 않는다. 디자인·문서 변경도 별도 승인 후 수행하고 사람이 확인한다.
3. 반영된 현재 기획과 번호 기준을 기준으로 R1 구현 착수 승인을 별도 받는다. 승인 전 executor를 호출하거나 코드 작성하지 않는다.
4. 이후 승인된 실행 단계에서만: levels/sprites 승인 데이터 → logic과 순수 테스트 → main/index 연결 순으로 최소 골격을 만든다. 중간 상태에서 미래 기능을 추가하지 않는다.
5. 집중 테스트와 승인 데이터 대조 후 실제 브라우저를 사람이 확인한다. M03에서 확정한 번호를 사용해 완료 근거를 보고하며 테스트 성공만으로 종료하지 않는다.
인계: 지금은 critic/architect의 읽기 전용 합의 검토만 적절하다. executor는 위 3 이후의 단일 목표 구현에만 사용한다. 성능 최적화용 autoresearch나 자율 범위 확장을 유도하는 ultragoal은 필요 없다.

## [S09] 수용 기준 초안 / Acceptance criteria
아래 R1-C 번호는 리뷰용 안정 ID이지 GAME_DESIGN 9장의 승인 번호가 아니다. M03 해결 전 완료 기준으로 확정하거나 현재 문서에 삽입하지 않는다.
- R1-C01: 승인된 단일 맵과 캐릭터·바닥·벽·8색이 실제 화면에 나타나며 승인되지 않은 오브젝트/문구가 없다.
- R1-C02: 통행 가능한 각 방향에서 한 번 누르면 논리 위치가 즉시 정확히 한 칸 바뀌며 대각 이동이 없다.
- R1-C03: 시각 위치만 출발 칸에서 목표 칸으로 120ms 동안 이동한다. 120ms 종료 이후 논리/시각 위치는 목표 칸에 일치한다. 프레임 간격 때문에 관측은 다음 표시 프레임일 수 있지만 논리 종료 기준을 늘리지 않는다.
- R1-C04: 애니메이션 중 새 방향 입력도 폐기하고 완료 후 자동 재생하지 않는다. 잠긴 동안 눌러 둔 키도 해제·재누름 없이는 추가 이동하지 않는다.
- R1-C05: 키를 누른 채 반복 keydown이 발생해도 한 칸만 이동한다. 해제 후 새로 누르면 다음 한 칸이 가능하다.
- R1-C06: 벽·맵 외곽을 넘어 논리 위치가 이동하지 않으며 막힌 입력의 애니메이션/잠금은 M02에서 승인한 정확한 규칙과 일치한다. 미승인 동작은 통과 기준으로 만들지 않는다.
- R1-C07: 15×11칸·16px 타일, 맵 위 16px 공간, 논리 240×192px, CSS 720×576px가 유지되고 창 크기에 따라 배율이 바뀌지 않는다. HUD 게임 값은 없다.
- R1-C08: 사람이 승인 번호와 연결해 실제 브라우저에서 위 동작을 확인했다. 자동 테스트나 fixture 스크린샷만으로 완료하지 않는다.

## [S10] 검증 / Verification
이번 단계는 계획 전용이므로 gate·테스트·lint·formatter·브라우저 실행을 하지 않는다. 검증 결과나 구현 성공을 주장하지 않는다. 아래는 향후 승인 이후에만 실행할 절차다.
- 명령: AGENTS의 `node --test test/`. package.json/npm/빌드 도구를 추가하지 않는다. 실제 Node ES module 로딩 방식은 승인된 파일 구성에서 확인하며 환경 불일치를 이유로 임의 의존성·모듈 체계를 도입하지 않는다.
- 실행: AGENTS의 `index.html` 브라우저 열기를 먼저 사용한다. file URL의 ES module 제한이 생기면 AGENTS가 허용한 `python3 -m http.server 8000`으로 실제 파일을 열고 경로를 보고한다. 서버 의존 기능을 만들지는 않는다.
- 수동 완료 보고는 M03 이후 확정된 9장 번호 또는 승인된 예외 계약의 번호로 무엇을 열고 볼지 명시한다.

## [S11] 집중 검증 설계 / Verification Plan
### 순수 로직
- 통행 가능한 4방향 각각 정확한 좌표 변화와 입력 원본 상태 불변 검증. 실제 승인 맵의 시작점/인접 벽 및 격자 치수를 대조한다.
- 수락 시각 t에서 논리 좌표 즉시 변경, t+119ms에 입력 차단, t+120ms에 새 누름 허용 검증. 시간은 주입하고 실제 대기 없이 시험한다. 기존 누름의 repeat는 경계 이후에도 금지한다.
- 이동 중 여러 방향 keydown을 보내도 큐가 없고 끝난 뒤 자동 이동이 없음을 검증. 그동안 눌러 유지한 키와 해제·재누름 사례를 구분한다.
- repeat=true 및 동일 키의 중복 keydown, keyup 후 새 keydown을 구분하여 한 번 누름 한 칸 보장. 잠금 중 keyup도 반영해 키가 영구 잠기지 않는지 검증한다.
- 승인된 벽/외곽에서 좌표 유지. 막힘의 시간/입력 처리 기대값은 M02 확정 후에만 작성한다.
- 시각 위치를 논리 판정에 섞지 않는 사례와 보간 종료의 목표 좌표 일치 확인. 기획 숫자에서 기대값을 가져오며 구현 결과를 복사한 테스트를 쓰지 않는다.
### 사람의 실제 브라우저 확인
- 승인된 실제 맵으로 index.html을 열어 캐릭터·바닥·벽과 팔레트를 확인한다. fixture 화면은 완료 증거가 아니다.
- 네 방향 단타, 길게 누르기, 이동 중 다른 키 누르기/유지, 해제 후 재누르기, 벽 접근을 직접 확인한다. 120ms는 테스트의 주입 시간 검증과 실제 시각 동작을 함께 확인한다.
- 실제 Canvas 속성/표시 크기와 맵/HUD 오프셋을 확인하고 창 크기를 바꿔도 고정 배율인지를 본다. UI 게임 값·미래 화면이 없는지 확인한다.

## [S12] 중요 항목 라우팅 / Escalation·Risk Gate
- M01 → 사용자 디자인 검토: 4·5·6장 상세와 시작점/맵 범례. 승인되지 않은 색·맵·도트로 실행하지 않는다.
- M02 → 사용자 동작 결정: 벽·경계 막힘 및 입력 잠금/애니메이션 처리. 테스트 기대값도 결정 후 작성한다.
- M03 → 사용자 의도 조정: 9장 유예와 완료 계약의 충돌. 무언의 예외나 선행 20항목 확장으로 해결하지 않는다.
- 계획 합의 ≠ M01/M02/M03 일괄 승인 ≠ 문서 수정 승인 ≠ 구현 착수 승인. 현재 상태는 계획 제안/중요 항목 미해결이다.
- 같은 실패 시도를 6번 넘게 반복하지 않고 AGENTS에 따라 중단·보고·재계획한다. 향후 범위나 확정 숫자를 바꿔야 하면 먼저 사용자와 기획 변경을 논의한다.

## [S13] 위험과 완화 / Risks and mitigations
- 미래 규칙 유입: 인터뷰는 출처 보조로만 사용하고 현재 기획서에 없는 HUD 값·등불·유령·타이머를 구현하지 않는다.
- 디자인 미정: placeholder로 우회하지 않고 M01 사용자 검토를 의존성으로 둔다.
- 입력 반복/시간 경계: keydown/key-up·repeat·잠금 상태를 분리하고 t+119/t+120과 재누름 테스트로 확인한다.
- 논리/시각 혼동: Canvas 없는 상태 변환과 렌더러를 분리하고 위치 판정은 논리 좌표만 사용한다.
- 브라우저 프레임 및 로컬 모듈 제한: 종료 목표는 120ms로 유지하되 표시 프레임 지연과 혼동하지 않는다. 허용된 정적 서버 대안과 순수 시간 검증을 사용한다.
- 완료 과장: M03 해결 전에는 goal 완료라 하지 않고, 이후에도 사람 확인과 승인 번호가 없으면 완료라 하지 않는다.

## [S14] ADR 초안
- 제목: R1 격자 이동의 최소 상태·렌더링 분리
- 상태: 제안. 디자인/완료 계약/구현 착수 미승인.
- 맥락: 현재 기획은 이동 수치만 확정했고 맵·색·도트·막힘 동작과 9장 완료 계약은 미해결이다.
- 동인: S03의 의도 충실성, 입력 정확성, 최소 실행·검증 비용.
- 검토 대안: S04 A(디자인 확정 후 최소 골격), B(임시 디자인 시제품).
- 결정 제안: A. 즉시 논리 이동을 순수 상태 전환으로 처리하고 120ms 시각 보간은 Canvas 렌더링 책임으로 둔다. 입력은 새 누름만 수락하고 애니메이션 중 것은 폐기한다.
- 결과: 미래 gameplay 없이 단일 목표에 집중하고 테스트와 사람 확인을 분리할 수 있다. 반면 미정 디자인·막힘·완료 계약이 해결될 때까지 실행을 시작할 수 없다.
- 승인·후속: M01~M03은 사용자에게 별도 라우팅하고 문서 검토 후 R1 구현 승인을 따로 받는다. 이 ADR 승인도 구체 맵·팔레트·배열을 승인하지 않는다.
