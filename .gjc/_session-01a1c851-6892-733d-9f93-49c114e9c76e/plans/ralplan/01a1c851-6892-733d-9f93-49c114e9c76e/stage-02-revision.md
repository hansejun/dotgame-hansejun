## [S08] 의존 순서 / Sequencing and dependencies
1. 의도 조정을 반영한 본 계획의 단일 목표·승인 경계·테스트 설계를 읽기 전용 검토한다. architect/critic은 M01/M02 값을 대신 결정하지 않는다.
2. 이후 별도 승인된 기획 보완 단계에서 M01 실제 디자인과 M02 막힘 동작을 사용자 검토로 확정하고, 9장에 R1 최소 번호 기준을 먼저 추가한다. 현재 요청에서는 이 단계를 실행하지 않는다.
3. 갱신된 기획과 번호 기준을 사람이 검토한 뒤 R1 구현 착수 승인을 별도 받는다. 미정 디자인이 남아 있으면 실행하지 않는다.
4. 향후 승인된 실행에서만 levels/sprites 승인 데이터 → logic과 순수 테스트 → main/index 연결 순서로 최소 골격을 만든다. 미래 기능은 추가하지 않는다.
5. 집중 테스트와 승인 데이터 대조 후 사람이 실제 브라우저를 확인한다. 9장의 확정 번호를 인용해 완료 근거를 보고한다.
인계: 현재는 architect/critic의 읽기 전용 검토만 적절하다. executor 등 구현 위임은 현재 요청에서 금지되며 향후 별도 승인 후에만 가능하다. autoresearch는 이 목표에 필요하지 않다. ultragoal을 포함한 어떤 실행 모드도 현재 무코드 요청에서는 사용하지 않는다. 향후 실행 모드와 무관하게 단일 목표와 별도 승인 범위를 준수해야 한다.

## [S09] 수용 기준 초안 / Acceptance criteria
R1-C 번호는 리뷰용 안정 ID다. 향후 문서 변경 승인 후 9장의 실제 번호로 반영·검토해야 하며 현재 이미 문서에 존재하는 번호로 주장하지 않는다. 이는 R1 최소 기준이며 R2의 20항목 이상 기준을 미리 확장하지 않는다.
- R1-C01: 승인된 실제 맵·캐릭터·바닥·벽·8색이 표시되고 미승인 개체·게임 값·문구가 없다.
- R1-C02: 통행 가능한 각 방향에 한 번 누르면 논리 위치가 입력 순간 즉시 정확히 한 칸 바뀐다. 대각 이동은 없다.
- R1-C03: 시각 위치만 출발 칸에서 목표 칸으로 120ms 동안 움직이고 완료 후 목표 칸에 일치한다. 논리 종료 기준은 120ms이며 프레임 간격에 따른 다음 표시 프레임 지연과 구분한다.
- R1-C04: 애니메이션 중 들어온 이동 입력은 폐기하고 끝난 뒤 자동 실행하지 않는다. 그동안 누르고 유지한 키도 해제·재누름 없이는 추가 이동하지 않는다.
- R1-C05: 길게 누르기와 반복 keydown은 한 번 누름의 추가 이동을 만들지 않는다. 해제 후 새로 누르면 다음 한 칸이 가능하다.
- R1-C06: 벽·맵 외곽을 넘어 이동하지 않으며 막힌 입력의 시각/잠금 처리는 향후 M02에서 승인한 규칙과 일치한다. 지금 미정 동작을 기대값으로 고정하지 않는다.
- R1-C07: 15×11칸·16px 타일·맵 위 16px 공간, 논리 240×192px와 CSS 720×576px 고정 3배가 유지되고 창 크기에 따른 반응형 확대나 HUD 게임 값이 없다.
- R1-C08: 사람이 실제 브라우저에서 위 동작을 확인하고 9장 확정 번호로 결과를 남긴다. 자동 테스트·fixture 스크린샷만으로 완료하지 않는다.

## [S10] 검증 / Verification
이번 단계는 계획 전용이므로 gate·테스트·lint·formatter·브라우저 실행을 하지 않는다. 제품 동작 성공을 주장하지 않는다. 아래 절차는 향후 승인된 실행에만 적용한다.
- 집중 명령: AGENTS의 `node --test test/`. package.json/npm/빌드 도구를 추가하지 않는다. 실제 ES module 로딩은 승인된 파일 구성에서 확인하고 환경 문제를 임의 의존성 추가로 우회하지 않는다.
- 브라우저: AGENTS에 따라 index.html을 연다. file://의 ES module CORS 제한이 있으면 이미 허용된 `python3 -m http.server 8000`을 선택적으로 사용한다. 이는 검증용 정적 서버이며 새 백엔드 기능이 아니다.
- 부모가 보고한 읽기 전용 환경 정보는 Node v22.20.0, Python 3.14.8이다. 본 계획 작성자가 직접 실행한 검증으로 주장하지 않는다.
- 완료 보고에는 사람이 무엇을 열어 무엇을 볼지 9장의 확정 기준 번호로 명시한다.

## [S11] 집중 검증 설계 / Verification Plan
### 순수 로직
- 통행 가능한 네 방향 각각 좌표가 정확히 한 칸 변하고 입력 상태 객체가 변이되지 않는지 검증한다. 승인 맵의 시작점·인접 벽·격자 치수도 대조한다.
- 수락 시각 t에 논리 좌표 즉시 변경, t+119ms의 새 입력 차단, t+120ms의 새 누름 허용을 검증한다. 시간 주입으로 실제 대기를 없애며 기존 누름의 반복은 종료 경계 후에도 거부한다.
- 이동 중 여러 방향 입력이 들어와도 완료 후 큐 재생이 없는지, 잠금 중 누른 채 유지한 키와 해제·재누름이 구분되는지 확인한다.
- repeat=true, 동일 키 중복 keydown, keyup 후 새 keydown을 분리한다. 잠금 중 keyup도 반영되어 영구 잠금이 생기지 않는지 검증한다.
- 승인된 벽·외곽에서 좌표를 유지한다. 막힘의 애니메이션·잠금 기대값은 M02 사용자 검토 이후 작성한다.
- 시각 보간이 논리 판정에 영향을 주지 않고 종료 시 목표 좌표와 일치하는지 확인한다. 기대값은 기획 수치와 승인 디자인에서 가져오며 구현 출력 복사는 금지한다.
### 사람의 실제 브라우저 확인
- 실제 승인 맵으로 index.html을 열어 캐릭터·바닥·벽·팔레트를 확인한다. fixture 화면은 완료 증거가 아니다.
- 네 방향 단타, 길게 누르기, 이동 중 다른 키 누르기·유지, 해제 후 재누르기, 벽 접근을 직접 확인한다. 120ms는 순수 시간 검증과 실제 시각 동작을 함께 확인한다.
- Canvas 논리 속성·표시 크기·맵/HUD 오프셋을 확인하고 창 크기를 바꿔도 고정 배율임을 본다. 게임 값·미래 화면이 없는지 확인한다.

## [S12] 중요 항목 라우팅 / Escalation·Risk Gate
여기는 향후 실행의 의존성과 승인 경계를 기록하며 현재 gate 실행 지시가 아니다.
- M01 → 향후 사용자 디자인 검토: 실제 도트·맵·8색. 이번 계획의 미해결 의사결정으로 강제하지 않고 실행 선행조건으로 유예한다.
- M02 → 향후 사용자 동작 검토: 막힘 처리. 이번에 값을 고르지 않고 구현·테스트 기대값 작성 전에 확정한다.
- 완료 계약 → 의도 조정 완료: R1 최소 기준을 9장에 선행 추가하고 R2 20항목 이상 확장은 나중에 한다. AGENTS 예외·변경은 없다. 실제 문서 편집은 현재 요청 밖이다.
- 계획 합의는 M01/M02 디자인 승인·문서 수정 승인·구현 착수 승인을 포함하지 않는다. 실행 선행조건이 충족되지 않으면 코드를 쓰지 않는다.
- 같은 실패 시도를 6번 넘게 반복하지 않고 AGENTS대로 중단·보고·재계획한다. 목표 범위나 확정 수치를 바꿔야 하면 먼저 사용자와 기획 변경을 논의한다.

## [S13] 위험과 완화 / Risks and mitigations
- 미래 규칙 유입: 인터뷰는 보조 근거로만 사용하고 HUD 값·등불·유령·타이머·화면을 추가하지 않는다.
- 디자인 유예를 임의 기본값으로 오해: M01/M02를 실행 선행조건으로 명시하고 placeholder로 우회하지 않는다.
- 완료 계약 조정이 현재 편집 허가로 오해: 방향만 확정되었으며 별도 문서 변경 승인과 사용자 검토 후 반영한다.
- 시간 경계·키 반복: keydown/keyup·repeat·잠금 상태를 구분하고 t+119/t+120 및 재누름 사례로 확인한다.
- 논리/시각 혼동: Canvas 없는 상태 변환과 렌더러를 분리하고 판정에 논리 좌표만 쓴다.
- 브라우저 프레임·로컬 모듈 제한: 120ms 종료 기준과 다음 표시 프레임을 구분하고 AGENTS의 기존 정적 서버 대안을 사용한다.
- 완료 과장: 9장 실제 번호와 사람 확인이 없으면 테스트 성공만으로 완료라 하지 않는다.

## [S14] ADR 초안
- 제목: R1 격자 이동의 최소 상태·렌더링 분리
- 상태: 제안. 완료 계약 방향은 의도 조정으로 확정되었으나 실제 디자인·문서 변경·구현 착수는 미승인이다.
- 맥락: 현재 기획은 이동 수치를 확정했고 실제 도트·맵·색·막힘 처리는 실행 전에 검토해야 한다. 사용자는 R1 최소 번호 기준의 9장 선행 추가를 선택했다. AGENTS 예외 없이 R2 20항목 이상 확장은 유지한다.
- 동인: S03의 의도 충실성, 입력 정확성, 최소 실행·검증 비용.
- 대안: S04 A(디자인 확정 후 최소 골격), B(임시 디자인 시제품).
- 결정 제안: A. 논리 위치는 입력 즉시 순수 상태 전환으로 바꾸고 120ms 시각 보간은 Canvas 렌더링 책임으로 둔다. 새 누름만 수락하고 애니메이션 중 입력은 폐기한다.
- 결과: 미래 gameplay 없이 단일 목표를 작은 테스트와 사람 확인으로 검증할 수 있다. 실행은 유예 디자인 검토·문서 반영·별도 착수 승인 이후에만 가능하다.
- 승인·후속: M01/M02는 향후 사용자 검토로 확정한다. R1 최소 번호 기준 문서 반영과 구현 승인도 별도로 받는다. 본 ADR 합의는 맵·팔레트·배열·막힘 동작을 승인하지 않는다.
