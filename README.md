# 폭풍 전의 등불

폭풍이 오기 전에 바다 유령을 피해 모든 등불을 켜는 한 화면 도트 게임입니다. 규칙·수치·맵의 기준은 [GAME_DESIGN.md](GAME_DESIGN.md)입니다. HTML, Canvas 2D, JavaScript ES modules로 만들었으며 의존성 설치나 빌드가 없습니다.

## 여는 법

프로젝트 폴더에서 다음 명령을 실행합니다.

```sh
python3 -m http.server 8000
```

브라우저에서 **http://localhost:8000/** 를 엽니다. 서버 종료는 실행한 터미널에서 `Ctrl+C`입니다. 이는 파일을 제공하는 정적 서버이며 게임 백엔드는 아닙니다.

- GitHub Pages: (배포 후 추가)
- GitHub Pages에 배포한 경우 해당 HTTPS 주소로도 실행할 수 있습니다.
- `index.html`을 더블클릭해 `file://`로 열지 않습니다. ES modules의 모듈 로딩이 브라우저의 로컬 파일 origin/CORS 보안 제한에 막히므로 HTTP 또는 HTTPS로 제공해야 합니다.

## 조작

- **방향키:** 한 번 눌러 한 칸 이동합니다. 이동 표시 중 입력과 길게 누른 키의 반복 이동은 무시합니다. 등불은 닿으면 자동으로 켜집니다.
- **Enter:** 타이틀에서 새 게임, 레벨 1·2 클리어에서 다음 레벨, 실패·최종 화면에서 타이틀로 돌아갑니다. 플레이 중에는 재시작하거나 일시정지하지 않습니다. 다음 동작에는 키를 놓았다가 새로 눌러야 합니다.
- 레벨 3을 클리어하면 추가 Enter 없이 최종 화면이 나옵니다. 점수는 레벨 사이에 누적됩니다.
- 효과음은 실제 Enter로 시작한 뒤 Web Audio로 합성합니다. 외부 오디오 파일과 배경음악은 없습니다.
- 최고 점수는 `localStorage`의 `dotgame.bestScore` 키 하나로 저장합니다. localhost와 GitHub Pages 기록은 서로 다릅니다. 저장이 차단되면 현재 탭의 메모리 기록으로 계속 플레이합니다.

## 레벨 하나 추가하는 법

현재 승인된 게임은 **3레벨**입니다. 아래는 확장 개발 절차이며, 이 안내가 새 레벨의 추가 승인을 뜻하지는 않습니다.

1. **기획 먼저:** `GAME_DESIGN.md`에서 레벨 수·등불 수·유령 수·제한 시간과 9장 수용 기준을 먼저 정하고 사람에게 승인받습니다. 5장에 새 **15×11** 문자 격자를 작성합니다.
   - `#`: 벽, `.`: 바닥, `P`: 시작점 한 개, `L`: 등불.
   - `a`/`b`/`c`: 서로 다른 유령의 순찰 경로. 각 경로는 길이 2 이상인 연속된 가로 또는 세로 직선이어야 합니다. 화면에는 경로 문자를 표시하지 않습니다.
   - 모든 통행 칸과 등불에 도달할 수 있어야 하며 유령이 움직이는 상태에서도 제한 시간 안에 안전하게 클리어할 수 있어야 합니다.
2. **격자 복사:** 5장 격자를 `src/levels.js`의 `levels` 배열 끝에 `{ duration: 제한시간ms, map: [...] }` 형식으로 그대로 복사합니다. 좌표나 등불·유령 배치를 별도 배열로 적지 않습니다. 기존 엔진은 배열의 마지막 레벨을 최종 화면으로 연결합니다.
3. **숫자 계약 갱신:** 현재 최고점 검증 상한 `4350`은 기존 3레벨의 등불 점수와 시간 보너스에서 나온 값입니다. 레벨을 늘리면 승인된 기획서의 점수 범위를 먼저 갱신하고 `src/storage.js`의 검증 상한 및 관련 테스트도 함께 바꿉니다. 기존 기록 형식이나 키를 임의로 추가하지 않습니다.
4. **테스트 추가:** `test/logic.test.js`에 기획서의 숫자를 기대값으로 사용해 격자 원문 일치·15×11 크기·시작점/등불/경로 개수·연결성·안전 클리어·제한 시간 경계·누적 점수·다음 레벨 초기화·새 마지막 레벨의 최종 화면을 검증합니다. 기존 3레벨 개수·시간·최종 위치를 가정한 테스트도 승인된 기획에 맞게 갱신합니다.

```sh
node --test test/
```

테스트 통과만으로 완료가 아닙니다. 실제 브라우저에서 기획서 9장의 해당 수용 기준을 사람이 확인해야 합니다. AGENTS.md는 사람이 관리하므로 에이전트가 수정하지 않습니다.
